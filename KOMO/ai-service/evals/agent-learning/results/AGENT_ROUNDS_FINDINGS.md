# 真实模型验证结论：补读有用，两轮尚未证明更优

2026-10-22。按AGENT_ROUNDS_SCOPE.md执行完5题×0/1/2轮，共30次真实DeepSeek请求，无自动重试，无补跑。服务返回的模型标识均为deepseek-flash；请求使用项目配置的deepseek-v4-flash。全量记录见agent-rounds-results.json，程序汇总见agent-rounds-summary.json，逐题答案与原文见AGENT_ROUNDS_REVIEW.md。

以下语义判断为助手逐项对照后的复核，不是用户评分、独立评测或自动事实认证。人工评分仍为空。

## 1. 确实有用：补回原先没有读到的关键依据

### a02：谁执行工具，结果怎样回到模型

初始上下文对两条暂定gold依据覆盖为0/2。0轮回答只好把结果回填机制标成“补充解释”，说明当前片段没有展开。一轮和两轮都补到2/2，并能引用原文解释应用侧执行工具、追加结果消息、再调用模型。

真实工具轨迹：一轮组读取块3和12；两轮组先读取块3并搜索“who executes the function result returned to the model”，随后停止。这里证明模型实际选择并执行了取证工具，不只是脚本替身成功。

### a15：同一节点里改变interrupt顺序

初始上下文对关键gold依据覆盖为0/1。0轮回答混用了并行中断ID映射的材料，无法明确说明同一节点内部按索引匹配；一轮和两轮都读取了块33—35及14—15，覆盖变成1/1，能区分节点内按索引匹配与并行分支按ID恢复。

以上是两个具体问题的证据与解释改善，不是全量准确率提升。

## 2. 没有证实：第二轮能带来额外证据

两轮组5道题的第二次模型决策全部返回无工具调用、选择停止。两轮组共10次实际工具调用，与一轮组同为10次；新增的是确认停止的模型请求，并没有第二轮新读取。

u01的一轮、两轮最终sources相同，两轮回答完成而一轮截断，不能归因于多读了材料：实际上并没有多读，且生成具有随机性、停止原因提示也不同。暂时不能据此决定“两轮最优”，也不能从这5题推断其他复杂任务只需要一轮。

## 3. 暴露的工程缺陷

### 最终生成未显式设置thinking，推理耗尽输出预算

15份回答中5份因finish_reason=length失败，全部出现在u01/u02。三份没有正文：u01-r1、u02-r0、u02-r1的completion_tokens和reasoning_tokens均为2048。另两份为u01-r0（1616推理tokens）与u02-r2（1291推理tokens），只留下部分正文。

取证适配器明确关闭thinking，最终生成适配器却未设置。提供方当前文档说明thinking默认开启，并且该模式下temperature无效。因此本批虽然请求参数相同、temperature都为0.2，却不能把这个值当成有效的低随机性控制。[官方说明](https://api-docs.deepseek.com/guides/thinking_mode/)

修复方向：显式决定阅读回答的thinking模式，或为启用推理的模式配置适当的总输出预算。不能仅增加工具轮数解决这个问题。本轮没有中途改变参数、增大上限或重跑。

### 补读挤掉了已经找到的能力限制

u02的初始sources包含“This works with all models that support tool calling”。一轮、两轮都选择补读错误处理相关块22—25、28—30，新增9142字符；最终组装优先放入新增片段，把包含上述条件的块10以及其他初始材料挤出12000字符预算。

所以此前“条件进入初始上下文”的修复不能保证经过Agent补读后仍保留。当前trace只标注遗漏的补读块，没有清楚标注被淘汰的初始依据。这是上下文管理缺陷，不能归因于模型本身。

修复方向：上下文组装需要记录被淘汰的所有证据，保护定义/能力条件等关键依据，并按问题去除冗长代码重复，而非简单“补读优先”。不能把所有初始片段都永久保留，否则又无法加入真正缺失的依据。

## 4. 引用合法仍不能证明结论成立

n01三组均没有编造P99毫秒数，并大体限定为当前片段。不过两轮组增加了一句“文中出现的毫秒一词只与timeout=10.0有关”，引用S6。S6实际是requests.get(url, timeout=10.0)及相关文字，没有声称出现“毫秒一词”。这个附加断言缺乏引用支持，引用编号检查却正常通过。

这直接说明：本轮代码保障了可执行范围、原文切片、编号存在及未完成状态，尚未保障逐项语义支持性。提示词中的“保留条件、不要越过证据范围”也可能执行得不一致。

另有u01-r2使用带空格的[ S4 ]。该ID本身存在，但当前解析器只识别标准[S4]形式；引用格式识别也需单独处理，不能把未被解析的引用当作已校验。

## 下一步优先级

1. 显式控制最终生成的thinking与输出预算，消除“推理耗尽预算却无正文”的问题。
2. 修复补读后的证据淘汰策略，保留条件与例外，同时记录被移除的初始证据。先用本次真实工具轨迹离线回放回归，减少新增模型用量。
3. 对关键结论做支持性检查；区分程序可验证的引用位置与仍需模型/人工判断的语义，不把编号合法等同于正确。
4. 在上述问题稳定后，再用新题和重复运行比较轮数。默认两轮目前只是预算，不是被本次实验验证的最佳值。

本批结果保留原样；尚未按上述发现继续修改生成模式、证据淘汰策略或默认轮数。
